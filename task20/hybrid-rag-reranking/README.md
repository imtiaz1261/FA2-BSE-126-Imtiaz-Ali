# Hybrid RAG System — BM25 + Vector Search + Cross-Encoder Reranking

Upgrades a standard RAG pipeline with hybrid retrieval (sparse BM25 +
dense vector search, fused with configurable weighting) and cross-encoder
reranking, then evaluates all four retrieval configurations head-to-head
with real IR metrics.

## Architecture

```
Query
  |-- BM25 retrieval (sparse, keyword-based)
  |-- Vector retrieval (dense, embedding-based, FAISS)
        |
        v
  Hybrid fusion (min-max score normalization + weighted merge + dedup)
        |
        v
  Cross-Encoder reranking (joint query-document scoring)
        |
        v
  LLM answer generation (Groq, grounded in reranked context)
```

## Setup

```
python -m venv venv
venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Your `.env` should contain your free Groq key (get one at
console.groq.com/keys):
```
GROQ_API_KEY=your_actual_key_here
```

## Usage

**1. Build the indexes** (downloads the embedding model on first run):
```
python scripts/ingest.py
```

**2. Ask a single question, seeing every pipeline stage:**
```
python scripts/run_query.py --query "What causes global warming?"
```

**3. Run the full evaluation** (compares all 4 methods, generates report):
```
python scripts/evaluate.py
```
This produces:
- `reports/evaluation_results.csv`
- `reports/metrics_comparison.png`
- `reports/latency_comparison.png`
- `reports/evaluation_report.md` — the full Phase 5 report

**4. Launch the web interface:**
```
streamlit run app.py
```
This opens a browser tab where you can type questions, adjust the
BM25/vector fusion weights live with a slider, and see every pipeline
stage (BM25 results, vector results, hybrid fusion, reranked results,
and the final answer) side by side. If you've already run
`scripts/evaluate.py`, the evaluation report and charts are also viewable
in an expandable section at the bottom of the page.

**4. Launch the web interface:**
```
streamlit run streamlit_app.py
```
This opens a browser tab where you can:
- Type a question and see BM25, vector, hybrid, and reranked results side by side
- Adjust the BM25/vector fusion weight live with a slider and see results change
- View the generated evaluation report and charts (after running `evaluate.py`) directly in the browser

## Why hybrid retrieval + reranking

- **BM25** matches exact keywords/terms — excellent for precise
  terminology, but blind to synonyms and paraphrasing.
- **Vector search** matches meaning — catches paraphrases and synonyms,
  but can miss queries that hinge on an exact rare term.
- **Hybrid fusion** combines both signals: min-max normalizes each
  retriever's scores to a comparable 0-1 range, then combines them with
  configurable weights (`BM25_WEIGHT` / `VECTOR_WEIGHT` in `config.py`).
  A document both methods agree on ranks higher than one only a single
  method found.
- **Cross-encoder reranking** re-scores the small hybrid shortlist by
  feeding the (query, document) pair jointly into one model — more
  accurate than either bi-encoder approach, but too slow to run against
  an entire corpus, which is why it only touches the already-narrowed
  candidate list.

## Evaluation metrics explained

- **Precision@K** — of the top K results, what fraction are actually relevant?
- **Recall@K** — of all relevant documents that exist, what fraction did the top K find?
- **MRR** — how early (at what rank) was the first relevant result found?
- **NDCG@K** — like precision, but rewards relevant results ranked *higher* more than the same result ranked lower — order-sensitive, unlike precision/recall.

## Testing performed before delivery

Since this sandbox has no network access to Hugging Face (so the actual
embedding model / cross-encoder model can't be downloaded here), testing
focused on everything that doesn't require that download:

- **BM25 retriever**: ran for real against the actual 12-document corpus
  and all 8 real evaluation queries — confirmed correct top-1 results,
  error handling on empty index, and a save/load round-trip.
- **Hybrid fusion**: tested with real BM25 results + realistic simulated
  vector results, confirming score normalization, weight validation,
  deduplication, and — concretely — that a document found by both
  retrievers gets correctly boosted above documents found by only one.
- **All 4 IR metrics**: every function hand-verified against
  independently calculated expected values, including NDCG's
  order-sensitivity property (same relevant doc scores higher at rank 1
  than rank 3).
- **Report generator**: ran the full CSV + chart (PNG) + markdown report
  pipeline against realistic synthetic 4-method comparison data —
  confirmed all files are written correctly and the report correctly
  auto-identifies the best-performing method.
- **Module imports**: installed the full real dependency stack
  (langchain, FAISS, sentence-transformers) and confirmed every module
  in the project imports without error.
- **Streamlit app**: launched `streamlit_app.py` for real (headless
  mode) and confirmed it serves HTTP 200 with no crash on load —
  including correctly showing the "run ingest.py first" guidance when no
  index exists yet.

**Not tested in this sandbox** (requires your machine's network access):
actual TinyLlama-style embedding model download, actual cross-encoder
model download, and the live Groq API call in `run_query.py`. Run
`scripts/ingest.py` and `scripts/run_query.py` on your machine to verify
these — the underlying logic they call has already been verified
correct.
